# Effekte pro Region Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Auf jede Region von Loop 2 lassen sich vier Insert-Effekte (Bitcrush, Filter, Flanger, Reverb) einzeln ein- und ausschalten; ein Regler-Satz pro Insert gilt in allen Regionen, die ihn nutzen.

**Architecture:** Neue DSP-Einheiten in `engine/fx/` (je Effekt eine Klasse, dazu `FxChain` mit Ein/Aus-Weichschaltung und Nachklingen). Die Engine rendert Loop 2 (Voice, auslaufender Voice, Vorhören von Loop 2) in einen eigenen Bus, schickt ihn durch die Kette und addiert ihn auf den Ausgang; Loop 1 bleibt trocken. Regler und Schalter (`FxSettings`) liegen im `Model`, im `PluginState` (XML), in den Presets (`bank.json` Version 2) und werden im Editor über einen Streifen unter der Loop-2-Spur und ein Panel mit vier Modulen bedient.

**Tech Stack:** C++20, JUCE 8.0.15, Catch2 v3.16.0, CMake.

**Spec:** `docs/superpowers/specs/2026-11-05-effects-design.md` (verbindlich; "Entscheidungen des Nutzers" und "Entscheidungen von Claude" gelten beide).

### Task 4: Effektkette

**Files:**
- Create: `engine/fx/FxChain.{h,cpp}`
- Modify: `engine/CMakeLists.txt`
- Test: `tests/test_FxChain.cpp` (eintragen bei `dc_tests`)

**Interfaces:**
- Consumes: die vier Einheiten, `FxParams`, `FxInsert`.
- Produces (Namespace `dc::fx`):
  - `class FxChain { public: void prepare(double sampleRate, int maxBlock); void reset(); void setParams(const FxParams& p); void setMask(std::uint8_t mask); void flush(); void process(float* l, float* r, int n); bool isActive(FxInsert i) const; bool anyActive() const; }`
  - `prepare`: legt alle Puffer an (auch Zwischenpuffer der Größe `maxBlock`), setzt zurück. `process` verarbeitet nie mehr als `maxBlock` Frames je Aufruf (Aufrufer teilt).
  - `setMask`: Bits der Inserts, die ab jetzt Eingang bekommen. Wirkt auf den nächsten `process`-Aufruf; der Übergang ist über einige ms geglättet (je Insert ein Gate-Gain `g` 0..1, ca. 5 ms).
  - `process` (in place, Bus rein, Bus raus = trockenes Signal plus Effekte): je Insert in Kettenreihenfolge. **Bitcrush und Filter:** `out = in + g * (behandelt(in) - in)`; ist `g` 0 und eingeschwungen, wird der Insert übersprungen (keine CPU) und sein Zustand gelöscht. **Flanger und Reverb:** Einheit bekommt `g * in`, ihr Ausgang (Effektsignal) wird zu `in` addiert; die Einheit läuft weiter, solange `g > 0` oder `tailLevel()` über einer sehr kleinen Schwelle liegt (etwa -100 dB), danach wird sie übersprungen und zurückgesetzt. Standard-Maske 0 und leerer Zustand: `out == in` exakt.
  - `flush()`: Ausblenden der Effektsignale der Kette über etwa 50 ms und danach Zustand löschen (Trockensignal bleibt unberührt); neue Maske und Regler gelten sofort weiter.
  - `isActive(i)`: der Insert wird gerade gerechnet (Gate offen oder Nachklingen). `anyActive()`: mindestens einer.

- [ ] **Step 1: Tests schreiben:** `FxChain: mask 0 passes the input through bit-exactly and nothing is active`. `FxChain: filter on and off crossfades without a step larger than the signal's own slope` (Sinus 1 kHz durch Tiefpass 200 Hz, Maske wechselt mitten im Block; größter Sprung zwischen Nachbarwerten unter 0.1 bei Amplitude 0.5). `FxChain: turning the reverb off keeps its tail and lets it die out` (Rauschen 0.5 s mit Reverb an, dann Maske 0 und Stille: Ausgabe in der Sekunde danach über -60 dB, nach 30 s `isActive(Reverb) == false` und Ausgabe exakt 0). `FxChain: an off insert leaves the dry signal at full level` (Reverb Mix 1, Maske 0: Ausgabe gleich Eingang). `FxChain: switching a mask bit inside a block of 64 frames is smooth` (Reverb an: Ausgabe endlich, kein Wert über 4). `FxChain: flush silences all effect output within 60 ms and leaves the dry signal` (Reverb klingt, `flush`, Eingang Stille: nach 60 ms exakt 0 und kein Insert aktiv). `FxChain: parameter changes do not click` (Filter Cutoff 200 Hz auf 8 kHz im laufenden Block: größter Sprung unter 0.1 bei Amplitude 0.5, Sinus 100 Hz). `FxChain: all four inserts on with extreme parameters stay finite and under 20 for 10 s of noise at 44.1, 96 and 192 kHz, blocks of 1 and 4096`.

### Task 5: Engine-Anbindung (Bus, Schalter, Vorhören, Nachklingen)

**Files:**

**Interfaces:**
- Consumes: `FxSettings`, `fx::FxChain`.
- Produces: `struct Model { LoopSlot loop1, loop2; RuleSet rules; FxSettings fx; };` und das Verhalten unten. Öffentliche Engine-Schnittstelle sonst unverändert; zusätzlich nur `bool fxActive() const` (any thread, relaxed gelesen aus einem Atomic, das `process` am Blockende setzt) für Tests und die UI.
- Verhalten (Spec "Engine" und "Entscheidungen von Claude"):
  - Bus: `tail_`, `voice_` und das Vorhören von **Loop 2** (Preview-Voices mit `slot == 1`) werden in einen Bus (zwei Puffer, in `prepare` mit `maxBlock` Frames angelegt) gerendert, durch `FxChain` geschickt und auf `l`/`r` addiert. Loop 1 und das Vorhören von Loop 1 gehen wie bisher direkt auf den Ausgang.
  - Maske: die Engine führt eine Ziel-Maske. Sie wird gesetzt: beim Start eines Loop-2-Voice (`startVoice`) auf `fx.maskFor(region2)` des aktuellen Models; beim Start eines Loop-2-Vorhörens auf die Maske der vorgehörten Region; bei `requestStop` auf 0 (Stille gezogen oder Gate endet); bei einem Voice, der sofort endet (keine Daten), auf 0. Nach einem nahtlosen Modelltausch (`adoptSwap`) wird die Maske für den laufenden Voice (`voice_.region2`, falls `Playing`) aus dem neuen Model neu bestimmt, damit ein im Editor umgelegter Schalter sofort für die klingende Region wirkt (Entscheidung dieses Plans, siehe Task 10 Hinweis). Ein Wechsel mitten im Block: die Engine merkt sich Wechselstellen (feste Obergrenze, zum Beispiel 32 je Block, bei Überlauf zählt der letzte Stand) und ruft `FxChain::process` in Segmenten auf, `setMask` vor jedem Segment.
  - Regler: jeder Block ruft `chain.setParams(model.fx.params)`.
  - Nachklingen: bei ungültigem Transport (Stop, kein Model) läuft die Kette weiter über einen Bus, der nur das Vorhören enthält, und ihr Ausgang wird auf die Ausgabe addiert; der Pfad `m == nullptr || !validTransport` darf die Kette nicht überspringen. Ein Transportsprung oder `resetPlayback` leert die Kette **nicht**.
  - Leeren: ein harter Neustart durch Modelltausch (Zweig `else` in `process` bei `rt != current_`) und `prepare` rufen `chain.flush()` (bzw. `reset()` in `prepare`); ein nahtloser Tausch tut es nicht.
  - Blockgröße: ist `n` größer als die in `prepare` angelegte Puffergröße, teilt `process` den Block in aufeinanderfolgende Scheiben (`t.ppq` je Scheibe um `Frames * ppqStep` weitergeschoben); `n == 1` funktioniert.
  - Endsumme: der Schlusslauf "nie nicht-endliche Werte" gilt weiter für die Summe.
