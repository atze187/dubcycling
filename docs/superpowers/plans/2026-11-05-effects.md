# Effects per Region Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On each region of loop 2, four insert effects (bitcrush, filter, flanger, reverb) can be switched on and off individually; one knob set per insert applies in all regions that use it.

**Architecture:** New DSP units in `engine/fx/` (one class per effect, plus `FxChain` with on/off soft switching and ringing out). The engine renders loop 2 (voice, fading-out voice, loop 2 preview) into a bus of its own, sends it through the chain and adds it onto the output; loop 1 stays dry. Knobs and switches (`FxSettings`) live in the `Model`, in the `PluginState` (XML), in the presets (`bank.json` version 2) and are operated in the editor via a strip below the loop 2 track and a panel with four modules.

**Tech Stack:** C++20, JUCE 8.0.15, Catch2 v3.16.0, CMake.

**Spec:** `docs/superpowers/specs/2026-11-05-effects-design.md` (binding; "Decisions by the user" and "Decisions by Claude" both apply).

### Task 4: Effect chain

**Files:**
- Create: `engine/fx/FxChain.{h,cpp}`
- Modify: `engine/CMakeLists.txt`
- Test: `tests/test_FxChain.cpp` (register under `dc_tests`)

**Interfaces:**
- Consumes: the four units, `FxParams`, `FxInsert`.
- Produces (namespace `dc::fx`):
  - `class FxChain { public: void prepare(double sampleRate, int maxBlock); void reset(); void setParams(const FxParams& p); void setMask(std::uint8_t mask); void flush(); void process(float* l, float* r, int n); bool isActive(FxInsert i) const; bool anyActive() const; }`
  - `prepare`: creates all buffers (also intermediate buffers of size `maxBlock`), resets. `process` never handles more than `maxBlock` frames per call (caller splits).
  - `setMask`: bits of the inserts that receive input from now on. Acts on the next `process` call; the transition is smoothed over a few ms (per insert a gate gain `g` 0..1, about 5 ms).
  - `process` (in place, bus in, bus out = dry signal plus effects): per insert in chain order. **Bitcrush and filter:** `out = in + g * (processed(in) - in)`; if `g` is 0 and settled, the insert is skipped (no CPU) and its state cleared. **Flanger and reverb:** the unit gets `g * in`, its output (effect signal) is added to `in`; the unit keeps running as long as `g > 0` or `tailLevel()` lies above a very small threshold (about -100 dB), after that it is skipped and reset. Default mask 0 and empty state: `out == in` exactly.
  - `flush()`: fading out the effect signals of the chain over about 50 ms and then clearing the state (dry signal stays untouched); new mask and knobs keep applying immediately.
  - `isActive(i)`: the insert is currently being computed (gate open or ringing). `anyActive()`: at least one.

- [ ] **Step 1: Write tests:** `FxChain: mask 0 passes the input through bit-exactly and nothing is active`. `FxChain: filter on and off crossfades without a step larger than the signal's own slope` (sine 1 kHz through lowpass 200 Hz, mask changes mid-block; largest jump between neighboring values below 0.1 at amplitude 0.5). `FxChain: turning the reverb off keeps its tail and lets it die out` (noise 0.5 s with reverb on, then mask 0 and silence: output in the second after that above -60 dB, after 30 s `isActive(Reverb) == false` and output exactly 0). `FxChain: an off insert leaves the dry signal at full level` (reverb mix 1, mask 0: output equal to input). `FxChain: switching a mask bit inside a block of 64 frames is smooth` (reverb on: output finite, no value above 4). `FxChain: flush silences all effect output within 60 ms and leaves the dry signal` (reverb sounding, `flush`, input silence: after 60 ms exactly 0 and no insert active). `FxChain: parameter changes do not click` (filter cutoff 200 Hz to 8 kHz in a running block: largest jump below 0.1 at amplitude 0.5, sine 100 Hz). `FxChain: all four inserts on with extreme parameters stay finite and under 20 for 10 s of noise at 44.1, 96 and 192 kHz, blocks of 1 and 4096`.

### Task 5: Engine integration (bus, switches, preview, ringing out)

**Files:**
- Modify: `engine/Engine.h`, `engine/Engine.cpp`, `engine/CMakeLists.txt`
- Delete: `engine/FxSlot.h`
- Test: `tests/test_Engine.cpp` (extend)

**Interfaces:**
- Consumes: `FxSettings`, `fx::FxChain`.
- Produces: `struct Model { LoopSlot loop1, loop2; RuleSet rules; FxSettings fx; };` and the behavior below. Public engine interface otherwise unchanged; additionally only `bool fxActive() const` (any thread, read relaxed from an atomic that `process` sets at the end of the block) for tests and the UI.
- Behavior (spec "Engine" and "Decisions by Claude"):
  - Bus: `tail_`, `voice_` and the preview of **loop 2** (preview voices with `slot == 1`) are rendered into a bus (two buffers, created in `prepare` with `maxBlock` frames), sent through `FxChain` and added onto `l`/`r`. Loop 1 and the preview of loop 1 go directly to the output as before.
  - Mask: the engine keeps a target mask. It is set: on the start of a loop 2 voice (`startVoice`) to `fx.maskFor(region2)` of the current model; on the start of a loop 2 preview to the mask of the previewed region; on `requestStop` to 0 (silence drawn or gate ends); for a voice that ends immediately (no data), to 0. After a seamless model swap (`adoptSwap`) the mask for the running voice (`voice_.region2`, if `Playing`) is re-determined from the new model, so that a switch toggled in the editor takes effect immediately for the sounding region (decision of this plan, see Task 10 note). A change mid-block: the engine remembers change points (fixed upper limit, for example 32 per block, on overflow the last state counts) and calls `FxChain::process` in segments, `setMask` before each segment.
  - Knobs: each block calls `chain.setParams(model.fx.params)`.
  - Ringing out: with an invalid transport (stop, no model) the chain keeps running over a bus that only contains the preview, and its output is added to the output; the path `m == nullptr || !validTransport` must not skip the chain. A transport jump or `resetPlayback` does **not** clear the chain.
  - Clearing: a hard restart by model swap (branch `else` in `process` at `rt != current_`) and `prepare` call `chain.flush()` (or `reset()` in `prepare`); a seamless swap does not.
  - Block size: if `n` is larger than the buffer size created in `prepare`, `process` splits the block into consecutive slices (`t.ppq` advanced per slice by `frames * ppqStep`); `n == 1` works.
  - Final sum: the final guard "never non-finite values" keeps applying to the sum.
