# Presets and Banks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The user saves the complete plugin state as a preset in a bank (folder with `bank.json` and `samples/`) via a button and a name, loads it again and passes a bank on as a zip.

**Architecture:** New UI-free unit `plugin/presets/` (bank format with JSON, file system store, zip export/import), in the processor only a restore of the state with the active preset, in the editor a new `PresetBar` in the top row. A loaded preset takes the same path as a host state (`applyState`, including relink and hash check).

**Tech Stack:** C++20, JUCE 8.0.15 (`juce::JSON`, `juce::ZipFile`), Catch2 v3.16.0, CMake.

**Spec:** `docs/superpowers/specs/2026-11-04-presets-design.md` (decisions 1 to 17 there are binding; their numbers are cited here as "Spec N").

## Review Focus

Inputs and states that the draft does not explicitly test and that are most likely to hit a user (each with a test in the named task):

1. Zip with entry `../x`, absolute path or drive letter: import rejects and creates nothing (Task 4).
2. Bank name `con`, `a:b`, `x.`, only spaces, differing only in upper/lower case from an existing bank: rejected (Task 2).
3. Two different loops with the same file name in one bank: second file gets a counter, none overwritten (Task 3).
4. Damaged or too-new `bank.json`: saving does not overwrite it (Task 3).
5. Export when a sample is missing: no zip is created, message names the file (Task 4).
